# E003 — Structural judgment before capability execution

Registered 2026-09-13. Parent: E002 at 67f4fdc79f6212f12e05854370c3d897cfc0e735. Status at registration: DESIGN; no E003 decisions or measured outcomes yet.

## Question

Can the current interactive assistant select a warranted intervention from the goal, evidence and available capability, rather than being assigned an E002 software condition? The structural object is the relation among authority, input meaning, eligibility, aggregation and output meaning—not a model brand or a fixed workflow.

The owner authorized continued research using structural judgment and explicitly allowed the current assistant as a subject. E001's authentic human-method comparison remains a separate pending experiment. E003 must not be described as that comparison or a model ranking.

## Subject, unit and candid limitation

One current-assistant, open-label development session with 12 committed case decisions. The assistant also designs the task families and evaluator. There is no blind evaluator, independent model sampling, empty-context reset or experimentally isolated model backend. Exact backend snapshot, tokens, human reading/review time and total cost are unmeasured. A decision artifact is an actual observable assistant choice; executing it again is not another model decision.

Before first outcome evaluation, preserve the public case pack, a separate result oracle, and then the assistant's choices. An answer key must not be supplied as a participant input. Code/oracle authorship in this same context still causes design exposure; file separation does not make the experiment blind. No claim of semantic holdout or independent preregistration is permitted.

## Tasks and available capability

Use 12 bounded synthetic quality/metric vignettes: invariant task meaning despite metadata or field-name changes; supported eligibility changes; known and missing unit conversion; percent versus parts-per-million precision; pooled versus equal-inspection-weighted rates; repeated defect events versus distinct units; a needed definition in an accessible document; unresolved equal-authority definitions; stale contract labels versus current authorized rules; and a valid zero denominator.

Start with the exact E002 capability source. It already supports LEGACY_V1 and EFFECTIVE_V2. A task requiring an already-supported option should not automatically cause new code. Extra data and public documents are evidence, not permission to change the goal. No customer or private repository data are used.

A choice may reuse an existing capability, bind/map/transform its boundary, replace a genuinely different calculation, retrieve a listed source, or ask a specific necessary authority question. These are reporting descriptions, not mandatory ordered steps. More than one valid method may satisfy a task. The primary evaluator scores actual outputs and authority handling, not matching a preferred action label. A separate descriptive intervention footprint records retained/changed components; it is not a calibrated effort/cost scale or proof of minimality.

## Execution sequence

1. Register this protocol before E003 case decisions and result execution.
2. Create a versioned synthetic case pack and separate independently implemented arithmetic oracle. Preserve exact input bytes and oracle version before choices. The same assistant authors both; independence here means separate implementation, not independent human judgment.
3. Display the participant view: goals, available rows, evidence references and source inventory, without expected results or recommended routes.
4. The current assistant writes a case-keyed initial decision record containing evidence references, a short public decision justification (not private reasoning), chosen action and component to retain/change. Where a listed source is needed, log the request and response before a follow-up decision. No simulated human response is substituted for a real one.
5. Freeze executable choices before first scoring. Execute all committed choices in a local read-only-data working copy. Retain every exception, incorrect result, unnecessary deferral and input mutation; no selective rerun.
6. If an implementation defect blocks useful continuation, preserve first-attempt evidence and at most one clearly separated repair result. Never rewrite a committed choice or first-attempt result.
7. Re-execute the exact source, inputs and choices on GitHub Actions as reproducibility verification, not extra independent cases. Preserve full synthetic output payloads, source hashes and results in the repository or an owner archive. No recurring inference service or new paid endpoint is required.

## Acceptance and falsifiers

A completed business result needs the exact requested metric, scope and numeric tolerance, with no invented facts, unapproved source edits or permission expansion. Correct abstention is recorded separately from completed work. Cases that cannot be resolved from the supplied evidence should include two admissible world states producing different answers; these witness cases demonstrate that guessing is not warranted. Such a witness is not a human answer and is not shown as an operational fact.

Fail the associated check if: rounded percentages are scaled when the requested ppm precision requires retained counts; available metric documentation is replaced by an unnecessary human question; a missing conversion factor is guessed; a stale contract label overrides current authoritative semantics; a new aggregation is presented as unchanged reuse; a harmless metadata difference causes rejection without a task-relevant reason; or a correctly blocked case is counted as completed.

Report counts of actual committed decisions, executed outputs, correctly blocked cases, incorrect completions, unresolved outcomes, external-source retrievals and proposed human questions. Questions selected in a synthetic vignette are not real participant interactions. Report implementation tests and deterministic replays separately. Do not infer causal superiority or operational ROI from this single self-authored session.
